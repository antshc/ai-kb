# NOT EVERY FAILURE GETS THE SAME FIX

Match the fix to the kind of failure.

## MEMORY

Missing a plain fact? Put it into memory — the cheapest move.

Examples:
- Forgets the user's preferred programming language.
- Repeatedly asks for a known project convention.

## HARNESS

Tool routing, read-back, guardrails? Fix the software around the model.

Examples:
- Uses the wrong tool for repository search.
- Modifies a file without validating the result.

## MODEL

Fails broadly and consistently? Only then touch the weights.

Examples:
- Consistently fails multi-step reasoning across tasks.
- Produces poor code across languages and repositories.
