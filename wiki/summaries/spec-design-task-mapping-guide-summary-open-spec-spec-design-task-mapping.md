# Spec → Design → Task: Mapping Guide

**Source:** `sources/open-spec-spec-design-task-mapping.md`

## Summary

> *"Reference specs for what needs to be built, design for how to build it."* **Specs answer "what done looks like."** **Design answers "where and how to implement it."** A well-formed task fuses both — so an implementer never needs to look elsewhere. --- | Source | Contribution
